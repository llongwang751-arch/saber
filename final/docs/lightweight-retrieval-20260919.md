# 轻量三路检索实现与服务器验收

2026-09-19，Python 版已经实现并部署 **Chroma 语义召回 + SQLite FTS5 BM25 + SQLite 图检索**。服务器仍为 `106.52.176.128`，通过本机 SSH 隧道访问 `http://127.0.0.1:18090/`。

## 实现范围

- **向量**：Chroma 1.5.9 本地持久化，显式提供远程 Embedding，不使用默认本地模型。按模型服务地址、模型名称与用户生成独立集合；维度不一致拒绝写入或检索。旧库向量没有可靠模型标识，因此初次重建重新计算，不直接复用。提供方若在同名模型下更换语义空间，需要重新发布索引目录。
- **关键词**：修正 BM25 分数方向；中文查询使用相邻双字短语，兼容现有单字索引。查询前修复缺失、已删除和文本过期的 FTS 条目。没有调整拒答阈值。
- **图检索**：SQLite 保存分块来源版本、实体提及、关系；保留同一实体在不同分块中的来源。匹配实体后最多扩展两跳，限制种子、邻居和返回数量。每条关系必须有对应的原文分块，且两端名称必须出现在原文中。
- **融合**：三路按照排名进行 RRF 融合，继续经过原有父段落去重、重排、拒答和引用校验。trace 记录各路状态、候选 ID 和索引完整度。
- **一致性**：SQLite 分块是事实来源，向量和图是可重建索引。查询前清理过期投影，命中还需匹配当前用户和内容/版本指纹。删除接口同步清理；绕过引擎直接删除的旧投影在后续检索时清理。此设计不是跨 SQLite/Chroma 的原子事务。
- **重建恢复**：向量逐批持久化，图按来源分块提交；失败后显式重建会跳过已完成条目。查询不会偷偷触发一整库模型重建。补齐 `Engine.rebuild_indexes()`，原有鉴权接口 `/api/rag/reindex` 现在能调用实际实现；状态接口显示 `rag_mode=lightweight`。

新上传资料会尝试生成两类索引；模型不可用时索引阶段会报错，已经持久化的原文和已完成索引保留，可用重建接口继续。尚未实现自动后台重建队列。

## 服务器

- 新代码：`/opt/agi-saber/releases/lightweight-20260919`；独立环境：`/opt/agi-saber/venv-lightweight`。
- 索引：`/opt/agi-saber/runtime/retrieval-v1`；源数据库继续使用现有 `application.db`。
- 切换前通过 SQLite backup 保存 `runtime/backups/pre-lightweight-20260919.db`。
- 实际重建：31 向量、31 已处理图分块、354 条带分块来源的关系记录。关系记录不是去重后的唯一语义关系数；本地评测抽取结果为 568 条，模型生成差异不能掩盖为同一图。
- 服务器三路探针均成功返回候选，重启后 31 向量及图记录保留。
- HTTP：未登录 401；登录、真实聊天、当前用户的索引重建通过；空知识库测试用户得到 0 分块，没有读到原知识库。
- 验收时进程内存约 215–288 MiB；这不是并发峰值承诺。原有 Worker 容器持续运行。

开关为 `AGI_RAG_LIGHTWEIGHT=1`，目录通过 `AGI_RAG_INDEX_DIR` 指定。安装使用 `pip install -r requirements-lightweight.txt`。维护者可在加载服务器环境变量后运行：

```bash
python scripts/reindex_lightweight.py --output runtime/lightweight-index-report.json
```

维护重建脚本应在维护窗口运行；正常在线单用户重建使用 HTTP 接口，避免多个独立进程同时写入嵌入式 Chroma。普通查询不应执行维护脚本。

若需回退代码，移走本次创建的 `/etc/systemd/system/agi-saber.service.d/lightweight.conf`，执行 `systemctl daemon-reload` 和 `systemctl restart agi-saber` 即可回到旧代码/旧虚拟环境。源数据库无需恢复旧快照，避免覆盖新聊天数据。

## 限制与后续

轻量配置限制每用户最多 10000 分块；查询会核对该用户的分块版本，尚未优化为增量变更日志。图检索没有 Neo4j 的查询语言、完整别名消歧和大图分析能力。实体名称出现不证明关系推理正确；图候选最终仍应回到原文。图功能用于 RAG，不等于已经完成长期记忆图的迁移。

后续补充：主 Agent 检查点恢复、当前 SQLite 路径的记忆事务一致性、每日异机备份已完成后续实现与验收，见 [恢复与备份验收](recovery-memory-backup-20260919.md)。自动索引重试、长期并发压测、独立质量测试集、legacy PG 全链路一致性及公网 HTTPS 仍未完成。当前 release 与回退方式以新验收记录为准。
