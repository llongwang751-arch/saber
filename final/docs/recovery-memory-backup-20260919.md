当前代码为 `/opt/agi-saber/releases/recovery-20260919-05`，复用 `/opt/agi-saber/venv-lightweight`。19 个发布文件逐项 hash 校验通过。应用仍通过本机 SSH 隧道 `http://127.0.0.1:18090/` 访问，前端恢复入口已随构建一起发布。

## 本轮落地

### 主 Agent 恢复

- 生产 GraphRuntime 持久化完整节点状态、参数、依赖、已完成结果与派发指纹，不再只有展示用步骤。
- 工具派发前必须成功保存检查点；检查点失败就中断，不能先执行再假装存档成功。
- 使用数据库 CAS 租约和心跳，租约覆盖工具图、最终回答、产物及最终快照。过期接管在更新语句中再次检查过期时间，避免读到旧值后抢走已续租任务。
- `/api/tasks/{task_id}/resume` 只接受任务 ID 与会话 ID。服务端读取执行图，校验用户与会话；客户端不能提供节点或改写参数。前端当前会话增加“恢复任务”入口。
- 跳过已完成节点；派发日志已提交的动作恢复保存的结果。执行中或超时后结果不明的操作返回冲突，禁止自动重放。恢复后的回复与完成快照在同一 SQLite 事务提交，重复恢复不会多写聊天记录。
- 实际子进程 `os._exit(23)` 测试覆盖“完成后崩溃，只执行后继”和“写入途中崩溃，禁止重放”。线上另用合成检查点验证 HTTP 行为，未杀死生产服务来模拟崩溃。

边界：这是**用户触发的检查点恢复**，不是开机后无条件重跑任务。旧版缺少完整检查点的任务不能可靠续跑。进程崩溃后需等待最长约 90 秒租约过期。恢复结果汇集工具图已提交的输出，不重新执行整段最终润色或生成产物；不承诺外部系统 exactly-once。Python 超时不能强杀任意底层线程，不确定结果仍需人工核对。

### 记忆一致性

- 当前部署的 SQLite 路径把偏好、长期事实、事实顺序和 outbox 投影事件放进同一事务。
- 每条用户消息分配持久化顺序号。较早消息的后台抽取晚返回，也不能覆盖较新更正；同一条消息中明确规则事实优先于 LLM 抽取。
- 同一事实保持原 ID，内容更正时清除旧向量。相同事实的后台向量补充可以成功，且不能降低规则事实优先级。
- 否定偏好清理相矛盾的偏好键；`姓名/名字/name/称呼` 归一。旧别名的带标签事实在下一次对应更正时被标为 superseded，并在同一事务发送投影删除事件，不直接抹掉历史记录。
- 只有事务提交后才更新共享缓存和“已记住”反馈。注入 outbox 故障验证三者一起回滚。线上真实模型两轮更正保持同一事实 ID；重启后更正仍在。

边界：本轮统一事务针对**线上实际使用的 SQLite 仓储**，不能据此宣称独立 legacy PostgreSQL 仓储也全部统一。进程内会话共享缓存已验证，多进程缓存广播失效未实现。开放语义别名、时间范围和复杂人物关系仍需要独立标注集；不是完整腾讯记忆服务移植。

### 自动备份与还原

- `agi-saber-backup.timer`：每天北京时间 03:15 触发，随机延迟最多 5 分钟，`Persistent=true`；开机漏跑会补执行。
- SQLite 使用在线 backup API 取得一致性快照，执行 `integrity_check`；打包数据库、`server.env`、`recovery.env`、应用配置和 `runtime/home` 产物。数据库以外的文件不承诺跨文件同一时刻快照。
- 本机 `/opt/agi-saber/backups`、异机 `/var/lib/agi-saber-backup/archives` 各保留最近 7 个成功归档。先完成新归档，才轮换旧归档。
- 传输使用专用 SSH key；接收账号只接受带文件名及 SHA-256 的备份流，不能执行任意 Shell 或转发端口；只允许主服务器来源 IP。目录/归档权限分别为 700/600。归档含运行凭据，属于私有运维备份。
- 异机校验成功并返回相同字节数及 SHA-256，备份任务才成功；失败在 systemd 中保留失败状态。未接入邮件、短信或其他告警通道。
- 已在两台服务器分别还原到独立演练目录，校验归档 hash、数据库完整性、用户/文档/分块/记忆/聊天行数；没有覆盖生产库。

已验证归档约 53.4 MB、包含 5 个账号、1 个文档、31 个分块、4 条长期记忆、21 条聊天记录。它生成于本轮合成记忆写入前，是当时的时点快照；之后验收账号新增的记忆记录不在该归档中。每日备份不等于实时复制，正常备份间隔内仍存在未备份的新写入。

**不包含正在写入的 Chroma/SQLite 图索引，也不是整机镜像或代码仓库备份。** 原文和分块在数据库中，恢复后可显式重建索引。服务器 release 与本地工作区另行保留；更换机器仍需部署代码和 Python 环境、恢复环境配置，然后重建检索索引。生成式图抽取可能和旧图不同，不能宣称字节级恢复旧索引。

运维检查：

```bash
sudo systemctl list-timers agi-saber-backup.timer
sudo systemctl show agi-saber-backup -p Result -p ExecMainStatus
sudo journalctl -u agi-saber-backup -n 20 --no-pager
```

手动执行同一备份流程：`sudo systemctl start agi-saber-backup.service`。

仅验证还原（目标目录必须不存在，不会覆盖生产数据库）：

```bash
sudo python3 /opt/agi-saber/ops/backup_server.py \
  --verify-archive /opt/agi-saber/backups/选定归档.tar.gz \
  --restore-dir /opt/agi-saber/restore-drills/新的演练目录
```

### 额外修复

1. 不合法执行图原先会清空依赖后继续执行；现在中断并要求重新规划。
2. Planner 原先把对象、数组和布尔值全部转成字符串。真实工具验收发现对象参数报错；现保留 JSON 类型，覆盖规划、重规划、执行与检查点。
3. 文档保存开关拒绝字符串布尔值，避免 `"False"` 因非空字符串而被当成开启；可保存文档的领域工具按副作用工具保护，不参加竞速或盲目重试。
4. 最终文件产物接入相同的执行策略与持久化派发日志；策略阻止时不落文件，同一调用读取保存结果，不确定失败停止。明确“不要保存/写入文档”不会触发关键词兜底产物生成。

## 三个上游的借鉴口径

**做的是轻量借鉴，不是整套搬入，也不是已经达到上游全部能力。** 上游版本与原始比较保留在 [开源项目对照](optimization-and-upstream-comparison.md)。

- **WeKnora 对照方向**：本项目落地 Chroma 向量、FTS5/BM25 关键词、SQLite 来源图的三路融合，以及版本/引用绑定、显式索引重建。没有接入一整套重型服务。原有知识库评测命中 36/36、带引用回答 34/36、无答案拒答 14/14；这些是本项目小语料成绩，不能当成与 WeKnora 的横向性能胜出证据。
- **TencentDB-Agent-Memory 对照方向**：在现有记忆链路增加分类、事实槽位、来源、纠错、否定处理、事务 outbox 和新旧事实顺序保护。没有独立部署腾讯记忆服务，也没有完成其全部图记忆与开放关系能力。
- **deepseek-harness 对照方向**：复用统一执行策略、审批/工具边界、持久化日志与 DAG 检查点。本轮补的是之前缺少的主 Agent 接线；独立 Harness 测试不能代替生产入口测试，因此另做了主图崩溃与线上接口验证。

下一阶段仍有价值的工作是：独立业务知识评测集、Agent 安全淘汰、后台索引失败自动重试、长时间并发压测及可选告警。公网域名/HTTPS 尚未配置；当前仍通过 SSH 隧道访问。
