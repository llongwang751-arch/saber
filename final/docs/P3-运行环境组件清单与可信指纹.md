# P3 运行环境组件清单与可信指纹

## 结论

生产 A/B 实验不能再把 `AGI_EXPERIMENT_RUNTIME_ENVIRONMENT_FINGERPRINT=<任意 64 位十六进制>` 当作运行环境证据。64 位格式校验只能证明“像 SHA-256”，不能证明它确实对应当前代码、模型、RAG 配置和知识库。

`internal/experimentation/runtime_identity.py` 提供了新的信任边界：

1. 构建或发布流水线生成严格的 component manifest；
2. manifest 以只读文件挂载到应用容器；
3. 部署控制器通过另一个通道注入该文件的 SHA-256；
4. 应用读取真实配置和当前代码 artifact，再与 manifest 逐字段比对；
5. 只有全部一致时，应用才计算并返回 `RuntimeIdentity`。

最终 fingerprint 没有输入参数，不能由请求方或实验创建者自报。

## 指纹覆盖范围

v1 清单严格绑定以下证据：

| 类别 | 字段 | 来源 |
|---|---|---|
| 运行编译器 | version、`runtime.py` artifact SHA-256 | 代码常量与当前应用文件 |
| 分析计划 | version、`service.py + statistics.py` artifact SHA-256 | 代码常量与当前应用文件 |
| RAG | `top_k`、`no_answer_threshold` | 当前 `APIConfig` |
| 模型 | LLM、Embedding、Reranker 精确标识 | 当前 `APIConfig`；Reranker 含主模型和回退实现 |
| 知识资产 | 语料 version/SHA-256、索引 version/SHA-256 | 索引构建/发布流水线 |
| 应用制品 | build SHA、完整 Git SHA、容器 image digest | CI/CD 与容器发布系统 |

分析计划版本当前为 `online-rag-itt-first-feedback-fixed-horizon-v1`。其语义是按用户分配、意向治疗分析、每位已曝光用户取首个合规反馈、固定样本与固定时长停止规则。只要这些规则发生变化，就必须升级版本；即使忘记升级，代码 artifact SHA 变化也会让旧 manifest 校验失败。

清单还使用严格字段集合，不能通过额外字段偷偷携带未绑定的模型覆盖、密钥或控制组配置。JSON 重复键、NaN、非法 digest 和超大文件均会拒绝。

## Component manifest 结构

下面仅展示结构，SHA 值不能直接复制到生产：

```json
{
  "schema_version": "agi-runtime-component-manifest-v1",
  "runtime_compiler": {
    "version": "rag-readonly-v1",
    "artifact_sha256": "<runtime.py 的实际 artifact SHA-256>"
  },
  "analysis_plan": {
    "version": "online-rag-itt-first-feedback-fixed-horizon-v1",
    "artifact_sha256": "<service.py 与 statistics.py 的实际组合 SHA-256>"
  },
  "rag": {
    "top_k": 3,
    "no_answer_threshold": 0.3
  },
  "models": {
    "llm": "qwen-max-2026-09",
    "embedding": "bge-m3-2026-08",
    "reranker": "llm_reranker:qwen-max-2026-09;fallback=cross_encoder:bge-reranker-v2-m3"
  },
  "knowledge": {
    "corpus_version": "pig-farm-kb-2026-09-14",
    "corpus_sha256": "<64 hex>",
    "index_version": "milvus-pig-farm-42",
    "index_sha256": "<64 hex>"
  },
  "application": {
    "build_sha": "<64 hex>",
    "git_commit_sha": "<完整 40 或 64 hex>",
    "image_digest": "sha256:<64 hex>"
  }
}
```

知识库 version 只是便于人阅读；真正参与完整性判断的是语料和索引内容 SHA-256。索引流水线必须对确定性的语料清单、chunk 结果和索引发布描述生成 digest，不能把日期字符串同时冒充 version 和 digest。

## 生产环境变量

运行时入口 `production_runtime_identity_from_environment(config)` 读取：

```text
AGI_EXPERIMENT_COMPONENT_MANIFEST_PATH=/run/agi/component-manifest.json
AGI_EXPERIMENT_COMPONENT_MANIFEST_SHA256=<manifest 文件原始字节的 SHA-256>
AGI_RAG_CORPUS_VERSION=<语料发布版本>
AGI_RAG_CORPUS_SHA256=<语料内容 SHA-256>
AGI_RAG_INDEX_VERSION=<索引发布版本>
AGI_RAG_INDEX_SHA256=<索引发布 SHA-256>
AGI_APPLICATION_BUILD_SHA=<应用构建 SHA-256>
AGI_GIT_COMMIT_SHA=<完整 Git commit SHA>
AGI_IMAGE_DIGEST=sha256:<镜像 digest>
```

manifest 文件必须使用绝对路径、普通文件、无任何文件系统写权限位，且不能是 symlink。部署时应使用只读 ConfigMap/Secret/volume，并设置 `defaultMode: 0444` 和 `readOnly: true`。应用容器还应以非 root 用户运行；只读权限检查不能替代容器权限隔离。

manifest 的 artifact SHA 必须由部署控制器单独注入，不能写在同一个 JSON 文件里自证。读取过程会检查文件描述符与路径的 inode/size/mtime/mode 快照，发现读取期间被替换或修改会失败关闭。

## 构建与启动流程

仓库提供可直接执行的中文 CLI：

```powershell
python scripts/build_runtime_component_manifest.py `
  --config config/config.yaml `
  --output D:/release-evidence/component-manifest.json
```

`--output` 必填；目标路径已存在时命令拒绝覆盖。命令在同目录创建临时文件并同步落盘，随后以不会覆盖并发目标的方式发布，设置为 `0444` 只读，再调用生产校验器复验。默认输出中文路径和三种安全摘要：artifact SHA、payload SHA、runtime fingerprint。输出白名单不包含配置对象、API Key、JWT Secret、数据库密码或环境变量全集。CI/CD 可加 `--json` 获取机器可读摘要：

```powershell
python scripts/build_runtime_component_manifest.py `
  --output D:/release-evidence/component-manifest.json `
  --json
```

构建流水线也可以使用与运行时相同的函数生成规范内容：

```python
from internal.experimentation.runtime_identity import (
    DeploymentComponentEvidence,
    canonical_component_manifest_json,
    component_manifest_from_runtime,
)

evidence = DeploymentComponentEvidence(
    corpus_version=corpus_version,
    corpus_sha256=corpus_sha256,
    index_version=index_version,
    index_sha256=index_sha256,
    application_build_sha=application_build_sha,
    git_commit_sha=git_commit_sha,
    image_digest=image_digest,
)
manifest = component_manifest_from_runtime(config, evidence)
payload = canonical_component_manifest_json(manifest)
```

流水线将 `payload` 写入构建制品并计算“文件原始字节 SHA-256”。运行容器不应现场生成或改写该文件。

启动时：

```python
from internal.experimentation.runtime_identity import (
    production_runtime_identity_from_environment,
)

runtime_identity = production_runtime_identity_from_environment(config)
```

任一证据缺失、格式错误、文件可写、artifact checksum 不一致，或当前配置/代码与清单不一致，函数都会抛出带稳定 `code` 的 `RuntimeIdentityError`。

## 与 ExperimentService 的集成

当前 `internal/application/api.py` 已在 `production_authenticated` 模式下把 `production_runtime_identity_from_environment(config)` 作为运行时提供器接入 `ExperimentService`。服务构造、就绪检查与各生命周期入口都使用完整的 `RuntimeIdentity`，不会把请求方或实验创建者提交的字符串当作可信证据。不要退化为下面这种只传字符串的方式：

```python
# 错误：又退化为只信一个字符串
ExperimentService(runtime_environment_fingerprint=runtime_identity.fingerprint)
```

当前集成遵循以下约束：

- `runtime_identity.production_verified is True`；
- readiness 暴露 `runtime_component_manifest_verified`、manifest payload SHA、compiler/analysis 版本；
- 创建实验时把 fingerprint、manifest artifact/payload SHA、compiler version 和 analysis plan version 写入预注册快照；
- start、分流、曝光完成、反馈和分析入口重新比对当前 `RuntimeIdentity`；
- 不允许旧的 `AGI_EXPERIMENT_RUNTIME_ENVIRONMENT_FINGERPRINT` 单独满足生产 readiness；
- 校验失败时原子地转为 `safety_paused`，禁止继续曝光和效果宣称。

生产应用使用可重复校验当前文件和部署证据的提供器：

```python
ExperimentService(..., runtime_identity_provider=runtime_identity_provider)
```

## 知识库变更规则

在线实验期间不能在同一个版本号下静默重建索引或修改语料。发生 ingestion、chunk 策略变化、Embedding 重算或索引重建时，索引流水线必须产生新的 version 和 digest。当前实验检测到 runtime identity 改变后应暂停；如需继续，应结束旧实验并用新预注册启动新实验。

如果业务必须持续写入知识库，应为实验使用带版本的只读快照或独立索引 alias。否则无法区分“候选策略效果”与“知识内容变化”。

## 已验证攻击面

聚焦单测 `tests/test_online_experiment_runtime_identity.py` 覆盖：

- 同一语义清单不同 JSON 排版产生相同 runtime fingerprint；
- RAG 配置、模型、知识/索引或发布证据变化导致旧清单拒绝；
- 任意 64 位字符串不能绕过文件 checksum 与逐字段运行态比对；
- 可写文件、symlink、重复 JSON key、额外未绑定字段拒绝；
- 代码 artifact、compiler/analysis version 和全部所需组件均进入清单；
- 环境入口缺任一部署证据都会失败关闭。

Windows 环境因创建 symlink 需要额外系统权限，会跳过 symlink 用例；Linux CI/生产环境执行该用例。
