# Mini-Drop 常驻后台接入

本项目完整 `main.build_deps()` 应用已独立部署至控制机，使用原 FastAPI 鉴权、文档与聊天路由、原 Vue 页面。Mini-Drop 通过 systemd 服务 `agi-office-backend.service` 与原生 Agent 的可信进程快照选择当前后台，每次诊断重新核对进程身份。它不是另写 `/query` 测试适配器。

业务入口位于 Mini-Drop 的“AI 诊断 → 接入服务 → 打开办公助手”。外层使用 Mini-Drop 浏览器会话，内部注册或登录本项目自己的账号。使用独立业务数据库，不修改本机原用户数据。当前云端采用本地词法检索和原项目配置的真实生成模型，未部署 Milvus。

部署设置 `AGI_LLM_ALLOW_MOCK=0`。`internal/llm/llm.py` 的 `_mock` 在该选项下显式报错，模型缺配置、同步与流式失败都不能用模拟答案冒充成功；默认开发行为仍允许 Mock。回归见 `tests/test_llm_no_mock_profile.py`。

业务运行数据在 `/var/lib/agi-office`，代码在 `/opt/agi-office/current`。`AGI_EVAL_TENANT_DIR` 必须指向可写的独立目录，不能在只读代码目录下创建 runtime。生成模型凭据通过 SSH 私下写入 `/etc/agi-office/backend.env`，没有提交到源码或测量报告。

本次 180 次真实知识库问答完成，Mini-Drop 四项采集与分析成功；AI 报告仍证据不足，不能说业务故障已被定位或修复。完整证据维护在 Mini-Drop 的 `docs/SERVICE_INTEGRATION.md` 与 `reports/business-acceptance/真实后台服务接入-20260913.md`。
