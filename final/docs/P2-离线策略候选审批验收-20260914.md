# P2 离线策略候选审批验收

日期：2026-09-14

## 结论

评测平台已经具备一条可审计的离线策略变更链：创建不可变策略版本，把 baseline/candidate 运行绑定到具体版本，在完全相同的数据集与评测协议上做成对比较，经过统计、发布门禁和 S0/S1 安全检查后，由不同人员审批，再显式激活或人工回滚。

这不是线上 A/B。它不分配真实流量、不记录真实曝光和业务 Outcome，也不会根据离线分数自动上线策略。所有接口和页面固定标记为 `offline_evaluation` / `offline_eval`。

## 已落地能力

- 不可变策略版本：Manifest 使用规范 JSON 和 SHA-256 内容寻址；相同内容幂等复用。
- Manifest 安全：递归拒绝 token、password、secret、authorization、cookie、private key 等敏感字段及常见凭据值；允许保存环境变量或密钥引用；限制为 256 KiB UTF-8。
- 运行绑定：评测 Run 可绑定 `strategy_version_id`，不存在的策略版本不能运行。
- 可比性约束：baseline 与 candidate 必须都已完成，必须使用同一个不可变数据集版本和 checksum，并完整覆盖全部 case，不能只挑交集。
- 协议冻结：比较 adapter 类型、发布门禁、评测器版本、数据来源、执行方式和合成数据标记；协议不一致时候选被阻断。
- 成对统计：Pass/Fail 使用双侧精确 McNemar；总体分数使用固定随机种子的 paired bootstrap 95% CI；少于 20 对样本或证据不足时明确返回 `inconclusive`。
- 安全硬门禁：candidate 的发布门禁失败、有逐例回归或出现 S0/S1 失败时，候选进入终态 `blocked`，不能审批或激活。
- 职责分离：候选创建者不能审批自己的候选；批准和激活是两个独立动作。
- 显式激活：审批通过不会自动改变策略指针，必须再次人工确认激活。
- 并发与审计：审批、激活、回滚使用行锁/CAS 语义；回滚带幂等键；策略审计事件追加保存操作者、时间、对象和变更摘要。
- Badcase 闭环：人工分诊只能进入 open/triaged/investigating；只有同一数据集版本、已完成 candidate 中对应 case 真实通过，才能验证为 resolved。
- 中文控制台：展示 current/previous、checksum、统计结论、CI、p-value、发布门禁、安全检查和阻断原因；危险操作需要确认。

## 状态机

```text
proposed --人工批准--> approved --显式激活--> activated
    |
    +--人工拒绝--> rejected

blocked  （统计、协议、发布门禁、安全或逐例回归失败；终态）
```

策略指针保留 current/previous。回滚只交换这两个指针，并产生不可重复的幂等审计事件。

## API

- `POST/GET /api/eval/strategies`
- `GET /api/eval/strategies/current`
- `GET /api/eval/strategies/{id}`
- `POST /api/eval/strategies/rollback`
- `POST/GET /api/eval/promotion-proposals`
- `GET /api/eval/promotion-proposals/{id}`
- `POST /api/eval/promotion-proposals/{id}/decision`
- `POST /api/eval/promotion-proposals/{id}/activate`
- `GET /api/eval/strategy-audit-events`

操作者只从服务端认证身份 `request.state.user` 获取，客户端不能在请求体里伪造 creator/reviewer/actor。

## 验证结果

```powershell
python -m pytest tests/test_evaluation_strategy_lifecycle.py tests/test_evaluation_strategy_statistics.py tests/test_evaluation_release_integrity.py -q
python -m pytest tests/test_evaluation_migrations.py -q
python -m pytest tests -q
Push-Location web
npm run build
Pop-Location
```

验收应保存同一提交的原始命令输出及跳过项；静态文档不固定会随参数化用例、环境和安全回归增长而变化的通过数。

全量回归入口固定为 `tests/`，避免误收集 `runtime/` 或 `tmp/` 中的临时测试副本。

## 面试中的准确说法

可以说：

> 我把离线 Benchmark 后的策略变更做成了不可变版本和人工审批状态机。只有同数据集、全量逐例、同评测协议的 baseline/candidate 才能比较；统计上同时看 McNemar 和 paired bootstrap，S0/S1、逐例回归和发布门禁是硬阻断。创建者不能自批，审批后也不会自动上线，激活和带幂等键的回滚都有审计记录。

不要说：

- “离线 Replay 已经证明线上业务提升”。
- “这里已经做完真实 A/B”。
- “系统会根据分数无人审核地自动进化”。
- “只要平均分上涨就能发布”。
