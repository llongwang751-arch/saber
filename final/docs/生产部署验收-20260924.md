## 本轮发现并修复的问题

### 1. SQLite 迁移级联删除：已回滚、修复并重新发布

首次升级中，Alembic batch 重建 users 表，而迁移连接启用了 foreign_keys=ON。
旧表 DROP 触发 ON DELETE CASCADE，造成新库中的旧文档、片段和历史消失；单纯 integrity_check / foreign_key_check 仍会通过，不能证明数据保留。

处理：
1. 停止新版本；完整保留故障现场。
2. 从停服前的完整状态备份恢复 SQLite、Milvus Lite 和业务文件，切回旧版本。
3. 核验恢复了 2 份文档、139 个片段、457 条历史。
4. 修复仅供迁移使用的专用连接：batch 期间关闭外键执行，迁移结束检查引用完整性。应用正常连接仍启用外键。
5. 增加“带旧业务数据升级”回归测试。
6. 对线上副本逐表比较旧字段哈希；正式发布前再次检查原始行，之后才开放端口。

最终旧数据逐行保留：
- 2 份文档及 2 个版本；
- 139 个 RAG 片段；
- 457 条原有聊天历史；
- 35 条偏好；
- 432 条长期记忆。

参考：[Alembic SQLite batch 与外键说明](https://alembic.sqlalchemy.org/en/latest/batch.html#dealing-with-referencing-foreign-keys)。

### 2. 其他修复

- “研究院”被误识别为“开展研究”，错误触发报告流程：已修复并增加测试。
- Milvus Lite 重启后加载既有集合，并让集合初始化失败向上传递，而不是报告假连接成功。
- 移植原云端批量 Embedding、分批索引优化，保留本地 FTS、租户过滤和持久化 outbox。
- Elasticsearch 768 MiB 限额导致内存回收与请求超时：调整到 1 GiB 后复验。
- 安装图谱多跳查询依赖的 APOC；使用固定镜像内 JAR，而非每次启动在线下载。
- 发布目录权限造成一次启动失败：修正权限后验证服务用户可进入。
- 保留 Mini-Drop 原有指标与请求观测包装；资源关闭交给新的统一生命周期管理。

**不能只切换旧代码软链接而保留新迁移版本数据库。** 旧代码不认识 0018。
回到最早旧版本前，先停写并保存当前完整状态，评估升级后的新增业务数据如何合并；再按备份匹配恢复应用库、向量目录、环境及服务增量配置。直接恢复旧快照会覆盖升级后的新增写入，禁止无人确认地执行。
本轮实际回滚发生在验收阶段，已验证恢复原始数据；不等于未来任意时间点都可以无损回退。
